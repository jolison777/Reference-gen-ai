Sub qry :
-------------
Qry embedded with in another qry is called sub qry
in sub qry , inner qry will executed first and outer qry will executed next

Types :
---------------

1) From Clause sub qry / inline view
2) normal subqry
3) nested subqry
4) multiple column subqry
5) co-related subqry
6) Scalar subqry

1) From Clause sub qry / inline view
   if we use the subqry in the from clause that is called inline view

 
    Dev notes: ( whenever we want to filter based on column aliaA /analytical funciutons,
      it is not possible since alias cannot be used in where clause
      in this case we have to push the qry as a inner qry
      and from the outer qry we can filter based on inner qry alias )
 
 
       

2)  normal Sub qry :
----------------------
    sub qry in where clause is called normal subqry
   
    if a where clause condition value can be get it from some other query then,
       we can create that query as inner query and match it as sub query

4) multiple column subqry

   it reduces number of layers in nested sub qry
   if we are having multiple columns in our where clause with comma seperation
   righthand side  must be a qry and not allowed direct values


 if LHS of the where clause having multile columns then
 RHS of the where clause must have qry not the direct values  

5) co-related subqry
   in co-related subqry, outer qry will be executed first
    and inner qry will be executed for each record of outer qry
   

  at least a value will be passed from outer qry to inner qry
 
   if use exists / not exists that qry must be a co-related subqry

  co-related subqry recomedded for very low volume of records in outer qry

  if we have huge volume of records in outer qry then, we have to use normal sub qry ,
          NOT THE corelated subqry


6) Scalar subqry

   subqry in select clause is called scalar subqry,
    in scalar sub query inner query must return only one row,
        if it returns more than one value then
        it ended with single row sub query returns more than one row error

   so to restrict the number of records in scalar sub qry( inner qry)
   we have to pass the value from outer to inner qry

   so it will become scalar co-related sub qry.
 
   Generally Scalar sub query is not recomended for production.
   It leads performence issue for huge volume of records in the outer query.
